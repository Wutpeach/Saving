# AE 外部调用的已知边界

来源：[Issue #1 首阶段实测报告](https://github.com/Wutpeach/Saving/issues/1#issuecomment-6679931759)。2026-11-06，Windows / Node.js 22.17.1 / AE 2026 26.3x87（build 87，en_US）；文件写权限已开启。架构约束见 [CLI 与 AE 宿主边界](../spec/cli-ae.md)，详细时序与请求 ID 留在 Issue，不重复保存原始证据。

## 可复用的实测结论

- AfterFX.exe -r + 请求/结果文件 IPC 在本机完成了无需 Saving 面板、无需第三方 MCP 的真实 CLI ↔ AE 闭环，成功读取版本、工程及中文合成信息；不会保存或切换工程。
- 本机标准引号传递含空格脚本路径时没有产生回执；无空格中文路径可执行。取得 Windows 8.3 短路径投递后，中文空格 IPC 目录及发行目录均成功。当前实现仅在需要时获取短路径；若仍含空白则返回 AE_SCRIPT_PATH_UNSUPPORTED，可改用完整路径不含空格的 IPC 目录。这是本机版本观察，不能推广到所有 AE 版本。
- 延迟探针确认投递进程退出早于真实结果；匹配回执才确认完成。1 ms 期限可返回明确超时，后续查询能恢复；不代表操作已取消。
- 连续 3 次和 3 路并发查询通过，隔离的请求 ID 未串回执；未做压力或长期稳定性测试。AE 的瞬时投递进程也可能触发多实例保守拒绝，且检查后新增实例仍有竞态。
- 同包 JSX 在不安装运行时 npm 依赖的解压目录中成功调用真实 AE。SavingHost.execute 对真实 app 的直接调用已通过；这仅验证宿主操作可复用，不等于验证 CEP evalScript。

## 验证层级及未知事项

- 无活动合成、脚本异常分支在真实 ExtendScript 引擎中使用函数局部模拟 app 测试；未清空用户工程或制造真实工程 API 故障。
- 自动化测试使用进程列表数据覆盖 AE 未运行、多实例和路径不可读的拒绝策略；未为此退出用户 AE 或启动第二个真实实例。
- 尚未实测：CEP evalScript、真实 AE 未运行的端到端调用、真实空工程、多真实实例寻址、脚本文件权限关闭、模态对话框阻塞、短路径禁用卷、其他 AE 版本、macOS 和高负载并发。
- 脚本加载、语法或回执写入失败可能只表现为 AE_TIMEOUT；不能仅凭超时断言原因。若外部调用跨版本不可靠，可评估自有 CEP 传输适配器，但面板常驻会改变运行前提，尚未选定或实现该替代方案。

## 复核与资料归属

使用已运行的单个 AE，先 npm ci、npm run build，再直接运行 node dist/cli.js host-info 或 project-info；需要中文与空格路径时指定 --ipc-dir。只读重复调用可检查 requestId 与 JSON 返回，不关闭或更改用户工程。操作前提及常用参数以根 README 为准。

一次性探针、原始回执及打包样本不纳入版本库，独立验证报告不再维护；有长期价值的自动化测试保留在 test/。历史开发/测试证据以 Issue 报告为准，不依赖临时本机文件。
